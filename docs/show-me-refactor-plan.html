3. Data-access interface

interface FileExplorerApi {
  listChildren(q: { folderId: string | null; query?: FileQuery; cursor?: string; limit: number },
               signal?: AbortSignal): Promise<Page<NodeSummary>>
  getNode(id: string, signal?: AbortSignal): Promise<NodeDetail>   // path (ancestors) + previewUrl
  search(q: { query: FileQuery; cursor?: string; limit: number },
         signal?: AbortSignal): Promise<Page<SearchHit>>           // flat hits with ancestor ids
  getStats(q: { query?: FileQuery }, signal?: AbortSignal): Promise<{ fileCount: number }>
  createFolder(i: { parentId: string | null; name: string }): Promise<NodeSummary>
  createFile(i: { parentId: string | null; name: string; category: FileCategory;
                  sizeInBytes: number; previewUrl: string }): Promise<NodeSummary>
  deleteNode(id: string): Promise<{ deletedIds: string[] }>
}
type Page<T> = { items: T[]; nextCursor: string | null; total: number }

Payload design

  • NodeSummary: includes parentId. A folder carries childCount, fileCount (descendant files) and matchCount when a filter is active. The chevron and badges come from these fields, so the client never counts a subtree.
  • getStats: feeds the header badge and "Showing X of Y files".
  • previewUrl: only returned by getNode, which keeps list payloads small.
  • Keyset cursor on (type, name, id), not an offset. With offsets, items get skipped or repeated when a create or delete happens between pages.

Mock backend

  • Seeded generator with a configurable size (?nodes=100000).
  • The shape includes one folder with ~5k children (pagination) and one chain ~20 levels deep.
  • Map<id, record> with pre-sorted childIds.
  • Each queryKey is evaluated once: one O(n) scan, then matchCount is pushed up to each ancestor, cached in an LRU cache like a server-side index.
  • Latency with jitter, AbortSignal, failure injection. URL config: ?seed=&nodes=&latency=&failRate=&failFirst=. failFirst=N fails the first N listChildren calls, so Retry can be tested deterministically.

4. State management

Normalized store (one per provider)

nodesById
listings[queryKey][folderId] =
  { ids, nextCursor, status, error }
expanded                // browse mode
filterExpanded[queryKey] // reset when filters change
selectedId, activeId, appliedQuery

Zustand createStore + context, so tests stay isolated. Clearing filters brings the browse expansion state back unchanged, as the app does today.

Loader

  • Deduplicates requests in flight per (queryKey, folderId, cursor).
  • Cancels stale filter requests with AbortController.
  • Requests the next page when the "load more" row scrolls into view.
  • On filter apply: search(limit 50), then expand the ancestors of those hits (D2).

Filters

  • Typing stays in local string state in the toolbar.
  • useDebouncedCallback from use-debounce (~250 ms) validates the draft, and only a valid FileQuery reaches applyFilters. Enter calls flush(); Reset calls cancel().
  • D3: inside applyFilters, a selected file that no longer matches (checked via its parentId chain and the shared matchesFile) is cleared in the same state update, and the change is announced. No effect.

CRUD cache updates

OperationStore change
CreateInsert at the sorted position in the parent's loaded listing (if that position is beyond the loaded page, bump only total); bump the parent's and ancestors' counts.
DeleteRemove the subtree ids, drop their listings, and clear selection or expanded state that pointed inside the subtree.
Either, while filteringDrop the filtered listings, since whether a node matches may have changed.

5. Rendering

Flatten, then virtualize

visibleRows = flatten(listings, expanded)
  → Row = node | loading | load-more | error
          { depth, posinset, setsize }

<VirtualTree>   // @tanstack/react-virtual, exact heights: folder 34 · file 50 · status 34 px
  ~40 mounted <TreeRow> regardless of tree size

Memoized; the cost is O(visible rows), not O(n).

Accessibility + re-render scope

  • Flat role="tree" with aria-level, aria-setsize, aria-posinset, aria-expanded.
  • Focus stays on the tree container; aria-activedescendant points at the active row, so focus isn't lost when rows unmount.
  • Keyboard navigation works on visibleRows indexes and calls scrollToIndex, with no DOM queries.
  • Each TreeRow is memo'd and subscribes to its own isExpanded / isSelected / isActive, so toggling one row re-renders only that row.
  • The preview is keyed by id and fetches getNode only after a file is selected.

Pagination: append on scroll (D8)

Each folder's children load in pages of ~100 with a keyset cursor. Most folders fit in one page and look exactly like today. Large folders end with one status row, drawn at the same indent and height as a folder row.
